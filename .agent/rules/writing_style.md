# Writing Style and Tone Guidelines

Strict rules for documentation, code comments, commit messages, and project communications:

1. **Prohibit AI Emoticons and Decorative Emojis**:
   - Do not use emoticons or emojis (e.g., 🚀, ✨, 💡, 🤖, 👥, 🧪, 📁, 📌, 🔥, 🎯, 🎉, etc.) in README files, documentation, markdown files, source code comments, commit messages, or UI copy.
   - Keep markdown headings, bullet points, and callouts clean and professional without decorative emoji prefixes.

2. **Prohibit AI-Style Fluff and Filler**:
   - Avoid generic conversational filler, sycophantic acknowledgments ("Certainly!", "Glad to help!"), and hyperbolic phrases (e.g., "delve into", "game-changer", "testament to", "in today's fast-paced environment").
   - Present technical information directly, concisely, and factually without introductory fluff or unnecessary summary conclusions.

3. **Professional Technical Precision**:
   - Maintain an engineering-focused, clear, and objective tone.
   - Focus on exact commands, configurations, schemas, architectural components, and verifiable facts.

4. **Mandatory Next Action Callout**:
   - Every response MUST conclude with a clear, explicit section indicating the next action for either the agent or the user (e.g., `### Next Actions` specifying **Agent Action** and/or **User Action**).
   - Never end a response ambiguously; always state who owns the next step and what action is required.
